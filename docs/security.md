# Security model

EpochGuard protects a configured buffered response route in an isolated deployment. It is experimental and is not a production authentication system, general factual verifier or all-route gateway firewall. [Architecture](architecture.md) is the detailed current contract; [evaluation](evaluation.md) identifies the finite tests and dated source observations.

## Attacker and trust boundary

Candidates, prompts, inference headers, provider responses/metadata and retrieved source bodies are untrusted. Tests include a relay changing a forwarded request while retaining its nonce, replaying/substituting receipts and adding unverified provider text. Clients cannot select evidence URLs, source mode, policy, keys or an authorization verdict. Unsupported prose cannot be partially released.

Trusted components are protected ingress, the pinned gateway/native plugin, Python verifier, operator configuration, receipt secret, local clock and host/container isolation. A compromised signing process, verifier, host or operator can defeat the guarantee. The private gateway-to-verifier HTTP hop has no independent authentication. Network isolation is part of the reference boundary, not cryptographic source authentication.

## Protected release

The protected ingress accepts buffered `POST /openai/v1/chat/completions`, retains the exact forwarded bytes, creates a fresh nonce, buffers the final response and validates its receipt before writing answer bytes. Missing, malformed, stale, replayed, cross-policy or mismatched receipts cause a fixed 503 without the upstream answer. Source-free readiness detects configured activation; each response still needs its own authentication. Readiness alone cannot authorize release or make revocation logically atomic.

`004g.receipt.v2` binds protocol, nonce, `004g.v1`/`bounded-prose-v1` policy, outcome, status, exact response digest, candidate digest, issued time and request-body digest using HMAC-SHA256. The signer derives the request digest from the actual raw body received in the pinned transport pre-hook; it does not trust a supplied digest header. Ingress independently hashes its retained forwarded bytes. Canonical encoding, strict fields/time checks and a fresh per-exchange nonce prevent tested downgrade/replay/substitution paths. See the exact [receipt contract](architecture.md#receipt-authentication-and-protocol-isolation).

Legacy 004D/004E explicitly use `004d.v1`. Those receipts do not provide G's exact request-body binding or metadata projection. G does not accept a legacy fallback. Do not market all receipt profiles as interchangeable security guarantees.

## Content, errors and resources

G independently parses the original response in Go and Python under nine ASCII sentence forms and two fixed source policies. Every admitted claim must be accounted for. Evidence identity, observation mode/times and claim bindings must agree. An authenticated response does not establish general semantic coverage or origin freshness.

Each fixed policy describes one singleton observation. A candidate may assert each policy only once, even when versions differ or recognized paraphrases vary. Independent Python/Go grammar checks refuse the whole repeated-policy candidate with `REPEATED_CLAIM`, no partial mappings and no retrieval; protected ingress returns 503 UNAVAILABLE without answer content. Python aggregation rejects duplicate policies even in caller-supplied COMPLETE sets; result schemas and Go validators reconstruct consistency rather than trust declared coverage or SUPPORTED verdicts. The [005D-S correction](task-005d-s.md) closes the demonstrated case where sequential observations supported different versions separately. Such language never becomes a source-verified 403 contradiction or receives multiple numeric report scores. Historical live runs predate this correction.

After Bifrost's typed-to-HTTP conversion, G replaces provider-owned metadata with a minimal envelope and signs those final bytes. Only the exact approved assistant content can carry factual answer text. IDs, model, usage, fingerprints, tier, extra/routing/nested metadata and arbitrary diagnostics are not admitted through an authenticated ALLOW. Ingress independently checks that representation. Length limits or a valid HMAC alone would not provide this property.

All supported claims allow 200. A validated older contradiction gives terminal 403; invalid coverage, unavailable evidence or failed bindings give 503. Typed policy refusals disable fallback. Genuine provider errors remain failed operations with their status and a fixed safe error category; their original arbitrary text is not verified content. No streaming answer bytes are released while awaiting verification. Application logs and test artifacts must not contain candidate/source bodies, secrets or raw receipts; the reference configs disable inference logging.

Ingress, verifier and Lab have separate bounded admission, body/header limits and deadlines. Uvicorn's server concurrency cap differs from verifier evidence admission. Tests cover overload and recovery, not CPU/memory isolation or a qualified global Bifrost execution deadline. Timeout may stop delivery without stopping all upstream work. Configuration/disable changes can race already-running work; finite restart tests do not prove atomic revocation.

The local [005D claim reporter](task-005d.md) is a separate diagnostic consumer of Python results or sanitized historical observations. It has no network client, enforcement hook, receipt key or browser diagnostics endpoint. Scores never authorize content and do not reconstruct Go validation. Trusted operator context selects fixture/live expectations; original evidence modes remain visible. Missing/invalid bindings or evidence yield null scores; historical imports cannot manufacture missing mappings/evaluation times. Reports contain no raw candidates, provider/source bodies, signatures or receipts. Static HTML revalidates the output schema, escapes values and disallows remote resources/scripts. A report failure cannot change an already computed verification verdict. Neither an editable score nor an exported digest proves source origin, freshness or protected release.

The isolated [005E combined profile](task-005e.md) defaults to simulated provider/source HTTP, private internal networks and zero real submissions. Live execution requires independent model and evidence opt-ins, a source/mode/image-matching offline suite no older than 24 hours, explicit private runtime files outside the repository and existing G-L source guards. It reuses the trusted strict adapter and fixed source policies. Sampling and verification share three retrieval invocations per policy; model and source reservations survive failures/cancellation. No reset endpoint, fallback retry, arbitrary source URL or model-selected live mode is added. Source observation changes are retained as inconclusive evidence, never repaired into an expected answer. The separate trusted `combined_qualification_diagnostics` flag permits the existing capped private stage sink for explicit prose/v2 configurations with either source mode; it cannot coexist with the old fixture-only flag or authorize delivery. Reports and runtime-code digests are trusted process observations, not external provenance or HMAC revalidation. The new profile has no published ports or browser-accessible diagnostics.

## Deployment and credentials

The separate [005C model profile](real-model-qualification.md) admits at most four explicitly authorized native Gemini generation submissions, with independent relay request/run budget reservations, size bounds and deadlines. Offline mode has no egress or credentials. Only the live relay can reach the fixed Google HTTPS endpoint; evidence remains simulated. Bifrost reads a process-only `env.*` key reference loaded from a private runtime file by the qualification launcher. The gateway and relay are trusted with that key in memory on their private HTTP hop. Gateway logs are suppressed because upstream diagnostic content is not qualified. Attempt counters and token estimates are application observations, not independent inference/billing evidence; timeout may leave billed remote work. The new draft-label analysis diagnostic requires separate authorization and credentials, never changes policies and never feeds release decisions. Model-produced policy names, URLs, hashes or verdicts have no authority.

Qualification response diagnostics retain only bounded structural categories, counts, booleans, visible-part hashes and fixed native stage enums. They never export raw text, thinking contents/signatures, provider error strings, credentials or receipts. Unknown fields/reasons are categorized. Trusted `qualification_diagnostics` is restricted to fixture-evidence prose with v2 receipts and writes only a private 0600 tmpfs file; no new client-visible field or network endpoint is added. Unadapted response bytes and shared candidate restrictions remain unchanged, including refusal of assistant reasoning/annotation unions. Diagnostic failure is non-authorizing. The first real-provider run's four safe refusals prove connectivity and non-release, not general correctness or successful verification; its exact structural cause remains unavailable in historical telemetry.

The later diagnostic run confirms a single visible text/signature shape being refused before verification. [005C-S](task-005c-s.md) demonstrates that pinned conversion can erase file-data parts, extra native candidates and signature attachment provenance while producing the identical typed response. Signature-only reasoning fields are insufficient to safely widen typed eligibility. The isolated [005C-T adapter](task-005c-t.md) enlarges the trusted relay boundary: when explicitly configured, it must account for the entire original UTF-8 JSON envelope before constructing a minimal text-only native response. All unknown fields, extra candidates/parts, reasoning, tools, multimodal output, grounding/citations and incomplete finishes refuse before conversion, including unsupported fields with empty values. A validated opaque same-part signature is removed; its value never affects the evidence input. Validation or adapter/diagnostic failure cannot fall back to forwarding the original success. Structural refusal becomes a safe 502 provider-output failure, distinct from authenticated 403 contradiction and 503 verification refusal. Original and projected digests depend on the trusted adapter; receipts authenticate the projected approved answer and request, not the original native envelope or a Google signature. No original bodies are persisted. Legacy checks, v2 receipts and minimal client envelopes remain unchanged. The [November 19, 2026 review](task-005c-t.md#reviewed-real-model-qualification--november-19-2026) met narrow real-model enforcement acceptance with simulated evidence, preserving these trust assumptions and original-envelope restrictions. Protected combined real-model/real-source execution remains unqualified.

Reference protected qualification profiles publish no gateway, verifier, provider or management ports. Within the Lab stack, the Lab alone publishes `127.0.0.1:8787`; its backend has two fixed ingress targets and does not join the private evidence network. The separate Explorer publishes `127.0.0.1:8791` on its own network. Both applications are loopback-only. An entry bridge is not an egress firewall. The fixture provider has no production authentication and must remain private. Direct gateway access can release unchecked content when the plugin is absent; ingress isolation is mandatory for the described protection.

Lab Host/Origin, non-simple JSON header and Fetch Metadata checks limit local browser abuse; only exact-root top-level GET document navigation may arrive cross-site. State-changing APIs still require the same origin. This is not identity/tenant authentication; trusted local processes can call it. CSP prevents framing. Do not bind the Lab publicly.

Runtime receipt keys are private files/volumes mounted only where needed. Qualification keys are disposable; production key provisioning, rotation, tenancy and client identity remain unqualified. Live-source secrets belong only in the explicitly authorized verifier's runtime file, never Compose output, process environment dumps, images or artifacts. Ordinary development uses simulated transports without source credentials. No CI job or installation command starts live retrieval or model calls.

## Unsupported and residual behavior

The separate [005I assessment path](#experimental-evidence-explorer) does not enlarge this protected scope.

## Experimental Evidence Explorer

[005J model diagnostics](task-005j.md) retain only fixed categories, allowlisted finish enums, bounded usage integers, configured limits/counts and redacted schema paths. Unknown provider enums and arbitrary extra-field names are never reflected. No model/input/source text, signatures, credentials, exception messages, Pydantic inputs/contexts or tracebacks enter the diagnostic logger. Per-response metadata is immutable and travels with its parsed record to avoid concurrent-request substitution. Logging failure preserves abstention; no diagnostics endpoint or new response field exists. These logs cannot retroactively diagnose responses for which the old process recorded no structural metadata, and provider counts are not independent billing evidence.

The separate [005I Explorer](task-005i.md) is an unsigned assessment service, outside the protected release boundary. Every application JSON response identifies `experimental-evidence`, `authorization=false`; errors abstain and malformed requests have a null claim. Accepted requests retain the exact original claim. It cannot issue an ALLOW, generate a receipt, choose evidence-policy modes or fall back to the protected verifier. Its Tavily `/search` client and dedicated Gemini instructions do not alter the existing `/extract` retriever or claim planner.

The [November 20 captured live result](task-005k.md#november-20-2026-explorer-live-observations) is operator-supplied screenshot/transcript evidence of an AI-assisted contradiction and application structural/corroboration acceptance. It does not independently attest provider origin, publisher independence, semantic truth or reliable availability, and cannot authorize arbitrary claims through the gateway. Other live attempts timed out or ended incompletely. Successful responses are not persisted by the backend and reload loses the displayed result; failure diagnostics remain structural only. No export/persistence feature is implemented. The protected 005E combined live path remains unqualified.

Search/model content is untrusted. Fixed HTTPS provider endpoints, no redirects/tools/arbitrary fetching, bounded JSON with duplicate/nonfinite-key refusal, complete source-set validation, numbered citation binding, exhaustive per-source assessment and exact snippet quotes limit structural misuse. At least two cited publisher groups and mutually consistent relevant stances are required for a conclusive result. Bundled PSL grouping, a small common-owner map and copy checks are heuristics; model relevance, factual scope, independence and entailment can still be wrong or prompt-injected. A valid schema/citation or two domains is not independent semantic proof. Publication dates are unverified metadata; retrieval today is not origin freshness.

Offline mode uses only explicitly simulated transports, no credential mounts or provider requests. Live startup requires independent Gemini/Tavily opt-ins and three distinct private files outside the repository. One reservation precedes search, counters survive failure/cancellation within the process, and no retry/fallback is configured. These are application planning limits, not provider billing attestation or restart-persistent spend controls. Operators must restrict credential-file ACLs and container readability; Windows ACLs are not inspected automatically. Timeout/cancellation can leave billed provider work.

Only loopback 8791 is published. Strict Host/Origin, Fetch Metadata and non-simple JSON header checks, no CORS, no-store/CSP, bounded body/admission and disconnect cancellation reduce local browser misuse. The UI renders untrusted content using text nodes and binds displayed results to the unchanged claim. This is no local identity/tenant authentication; trusted local processes can invoke it and its bridge is not an egress firewall. Live operation sends the claim to Tavily and the claim/excerpts to Google. The original Lab remains independently runnable at 8787. No public deployment, general accuracy, injection immunity or combined protected qualification follows from these tests.

## Protected residual scope

Streaming, arbitrary prose/sources, alternate routes, passthrough, Warp background work and production providers are outside this release boundary. API routes can skip transport hooks; some Warp errors are HTTP 200 envelopes. Route-audit findings are narrower than an all-route security claim. Built-in caching remains disabled: asynchronous writes can precede enforcement or follow deletion. An owned verified cache and atomic revocation are proposals only.

Source hashes attest checked content within the trusted verifier, not independent origin freshness, billing, or provider honesty. The November 15 real-source qualification used a controlled provider; the November 19 real-Gemini qualification used simulated evidence and tightly controlled prompts. Neither establishes general correctness or a combined real-model/real-source execution. Model planning remains non-authorizing and unqualified for real-model quality. Other Bifrost versions or plugin combinations need fresh conversion/order/ABI/security tests. See [compatibility](compatibility.md) and [disclosure instructions](../SECURITY.md).
